## III.G Evaluation Traces & Locality Patterns

Nine deterministic synthetic workloads are generated by `scripts/gen_traces.py`. Each trace exercises a specific spatial–temporal locality pattern designed to expose architectural differences between the 2-way set-associative and direct-mapped caches. All addresses are word-aligned (4-byte boundary) and confined to the 16 KB main memory range (`0x00000000` to `0x00003FFC`). Trace generation is fully reproducible across platforms through deterministic seeds and constant address arithmetic.

### T1: Sequential Stream (`seq_stream.txt`) – 256 accesses

**Locality Pattern:** Pure spatial locality with zero temporal reuse. 256 consecutive word reads at stride = 4 bytes traverse addresses `0x0000` to `0x03FC` (1024 bytes total).

**Expected Behavior:** Since each 16-byte cache block contains 4 words, the first access to each block is a compulsory miss (cold start), while the subsequent 3 accesses in the same block hit. This yields an expected hit rate of exactly **75.00%** (192 hits / 64 misses) for both caches, as sequential traversal creates no index conflicts within a single pass through the address space.

**Purpose:** Establishes the baseline spatial-locality performance floor and validates that the 4-word block fetch pipeline works correctly.

---

### T2: Small Loop (`small_loop.txt`) – 640 accesses

**Locality Pattern:** Strong temporal and spatial locality. A 256-byte working set (64 words at addresses `0x0400` to `0x04FC`) is iterated 10 times, modeling a tight inner loop.

**Expected Behavior:** The 256-byte footprint requires exactly 16 cache blocks (256 B / 16 B), fitting easily within the 1 KB capacity of both caches. The first iteration incurs 16 compulsory misses; all 9 subsequent iterations achieve 100% hits. Expected hit rate: (640 − 16) / 640 = **97.50%** for both caches.

**Purpose:** Demonstrates the fundamental temporal-locality benefit of caching for loop-dominated code. Confirms that both architectures correctly retain and serve repeated accesses from cached blocks.

---

### T3: Ping-Pong Conflict (`pingpong.txt`) – 200 accesses

**Locality Pattern:** Alternates between two memory addresses mapping to the **same cache line/set** but with different tags:
- Address A: `0x0020` → Direct-Mapped Line 2, Tag 0; 2-Way Set 2, Tag 0
- Address B: `0x0420` → Direct-Mapped Line 2, Tag 1; 2-Way Set 2, Tag 2

**Expected Behavior:**
- **2-Way Set-Associative:** Way 0 holds Address A, Way 1 holds Address B. After 2 cold misses, both blocks coexist in the 2-way set. Remaining 198 accesses all hit. Hit rate: **99.00%**.
- **Direct-Mapped:** Only 1 line available for Set 2. Every access evicts the previous block, causing complete thrashing. Hit rate: **0.00%**.

**Purpose:** This is the **canonical demonstration** of why set associativity exists. The 2-way cache eliminates all conflict misses with just one extra way, achieving 99% hits where the direct-mapped baseline achieves 0% — a performance gap of **6.6× in total cycles** (424 vs 2,800).

---

### T4: 3-Way Cyclic Conflict (`cyclic3.txt`) – 300 accesses

**Locality Pattern:** Three addresses mapping to the **same set** accessed in repeating cyclic order A → B → C → A → B → C → ...:
- Address A: `0x0030`, Address B: `0x0430`, Address C: `0x0830`

**Expected Behavior:**
- **Direct-Mapped:** Thrashes completely (0% after cold misses).
- **2-Way LRU:** The 2-way set can hold at most 2 blocks. When block C is needed, the LRU policy evicts the least recently used block (which is always the one that will be needed next in the cycle). This is the classic **Bélády anomaly pattern for LRU** where a working set of N+1 = 3 blocks defeats an N = 2-way LRU cache. Hit rate: **0.00%** after cold misses.

**Purpose:** Demonstrates the **pathological worst case** for LRU replacement. Despite the extra hardware cost of 2-way associativity, LRU cannot help when the working set exceeds the set capacity by even one block and the access pattern is perfectly cyclic.

---

### T5: Strided Access (`strided.txt`) – 256 accesses

**Locality Pattern:** 64-byte stride (4 cache blocks apart) across 8 distinct addresses, repeated for 32 passes. Accesses addresses `0x0100`, `0x0140`, `0x0180`, ..., `0x02C0` (every 4th set in the cache).

**Expected Behavior:** The 8 accessed blocks (128 bytes) fit entirely in both caches. After 8 compulsory misses in the first pass, all 248 subsequent accesses hit. Hit rate: **96.88%** for both caches.

**Purpose:** Validates correct handling of non-unit strides that skip cache sets, ensuring that the index hashing and tag storage work correctly when only a sparse subset of sets is exercised.

---

### T6: Pseudorandom Access (`random.txt`) – 300 accesses

**Locality Pattern:** Uniform random word addresses drawn from the full 16 KB range using deterministic seed 42. Minimal temporal or spatial locality.

**Expected Behavior:** Very low hit rate (typically 5–15%) for both caches, as accesses are scattered across the entire address space. The 2-way cache may achieve a slightly higher hit rate due to its ability to retain two blocks per set, but the improvement is small since the access pattern lacks exploitable structure.

**Purpose:** Stress-tests the cache controller FSM, memory bus handshaking, and data integrity verification under random, unpredictable access patterns. Validates robustness of golden memory cross-checks across diverse address interleavings.

---

### T7: Mixed Read/Write (`mixed_rw.txt`) – 300 accesses

**Locality Pattern:** 70% reads and 30% writes (deterministic seed 12345) within a hot 512-byte region (128 words at addresses `0x0800` to `0x09FC`). Write data is tagged with a unique identifier (`0xAA000000 | access_index`).

**Expected Behavior:** The 512-byte working set (32 cache blocks) fits comfortably in the 1 KB cache. Both caches achieve approximately **81.33%** hit rate. The write-through no-write-allocate policy means write misses bypass the cache entirely, while write hits update the cache and write through to memory.

**Purpose:** Verifies the Write-Through No-Write-Allocate policy under mixed traffic:
  - Write hits update both the cache data array and main memory.
  - Write misses go directly to memory without cache allocation.
  - Subsequent reads return correct data regardless of whether the preceding write was a hit or miss.
  - Golden memory verification confirms end-to-end data integrity.

---

### T8: Large Loop (`large_loop.txt`) – 384 accesses *(Member 4 Extension)*

**Locality Pattern:** A loop iterating over a 1.5 KB working set (384 words = 1536 bytes = 96 cache blocks of 16B each), reading 1 word per block across 4 iterations. The working set intentionally **exceeds** the 1 KB (64 block) cache capacity.

**Observed Results & Architectural Analysis:**
- **2-Way Set-Associative (32 sets):** 96 blocks / 32 sets = **exactly 3 blocks per set**. Every single set is subjected to a cyclic 3-way conflict (A → B → C → A → B → C). Consequently, LRU replacement exhibits catastrophic cyclic thrashing across every set, yielding **0 hits / 384 accesses (0.00% hit rate, 5,376 cycles)**.
- **Direct-Mapped Cache (64 lines):** 96 blocks mapped modulo 64. Lines 0..31 experience aliasing between 2 blocks and thrash completely. However, lines 32..63 (32 lines!) only ever receive a single block. After the initial pass of 32 cold misses, these 32 lines **hit on every subsequent pass** (3 passes × 32 lines = 96 hits), achieving **25.00% hit rate (4,224 cycles)**.
- **Insight (Interview Prep Q5):** This empirical demonstration cleanly explains why direct-mapped caches can paradoxically outperform 2-way LRU on loops whose footprint falls between $C$ and $2C$ capacity: direct-mapped caches allow non-colliding lines to hit, whereas LRU can suffer 100% pathological eviction across all sets simultaneously.

---

### T9: Read-Mostly Stream with Hot Region (`hot_stream.txt`) – 400 accesses *(Member 4 Extension)*

**Locality Pattern:** Models a realistic concurrent workload:
- **Hot Region (70% probability):** Random reads within a 128-byte working set (32 words at `0x1000` to `0x107F`, 8 cache blocks).
- **Cold Stream (30% probability):** Linear sequential reads advancing through a 2 KB streaming buffer (`0x2000` to `0x27FF`, 128 cache blocks).

**Observed Results & Architectural Analysis:**
- **2-Way LRU:** Achieves **363 hits / 400 accesses (90.75% hit rate, 1,244 cycles)**. The extra associative way acts as a dynamic shield: even when cold streaming blocks transiently map into the same sets as hot data, hot blocks remain protected in the complementary way.
- **Direct-Mapped:** Achieves **347 hits / 400 accesses (86.75% hit rate, 1,436 cycles)**. Every time a streaming cold access aliases with a line containing hot data, it evicts the hot block, causing subsequent re-accesses of that hot data to miss.
- **Benefit:** 2-way set associativity provides a **+4.00 percentage point higher hit rate** and reduces total execution time by **192 clock cycles (13.4% faster)** under realistic stream-interference conditions.

### B. Analytical Cycle Verification

For all read-only workloads, the measured cycle count matches the analytical equation to the exact single cycle:

$$\text{Total Cycles} = (\text{Hits} \times 2) + (\text{Misses} \times 14)$$

Where:
- Read Hit Latency = **2 clock cycles** (IDLE → LOOKUP → Ready)
- Read Miss Latency = **14 clock cycles** (IDLE → LOOKUP → MISS_FETCH [8-cycle RD_LAT + 4-cycle burst] → Ready)

**Analytical Proofs:**
- `seq_stream`: $(192 \times 2) + (64 \times 14) = 384 + 896 = 1,280$ cycles ✓
- `small_loop`: $(624 \times 2) + (16 \times 14) = 1,248 + 224 = 1,472$ cycles ✓
- `pingpong` (2-Way): $(198 \times 2) + (2 \times 14) = 396 + 28 = 424$ cycles ✓
- `pingpong` (Direct): $(0 \times 2) + (200 \times 14) = 0 + 2,800 = 2,800$ cycles ✓
- `cyclic3`: $(0 \times 2) + (300 \times 14) = 0 + 4,200 = 4,200$ cycles ✓
- `strided`: $(248 \times 2) + (8 \times 14) = 496 + 112 = 608$ cycles ✓
- `random` (2-Way): $(22 \times 2) + (278 \times 14) = 44 + 3,892 = 3,936$ cycles ✓
- `random` (Direct): $(18 \times 2) + (282 \times 14) = 36 + 3,948 = 3,984$ cycles ✓
- `large_loop` (2-Way): $(0 \times 2) + (384 \times 14) = 0 + 5,376 = 5,376$ cycles ✓
- `large_loop` (Direct): $(96 \times 2) + (288 \times 14) = 192 + 4,032 = 4,224$ cycles ✓
- `hot_stream` (2-Way): $(363 \times 2) + (37 \times 14) = 726 + 518 = 1,244$ cycles ✓
- `hot_stream` (Direct): $(347 \times 2) + (53 \times 14) = 694 + 742 = 1,436$ cycles ✓
- `matrix_walk`: $(448 \times 2) + (64 \times 14) = 896 + 896 = 1,792$ cycles ✓

For `mixed_rw` (which contains 197 reads and 103 writes):
$$\text{Total Cycles} = (165 \times 2) + (32 \times 14) + (103 \times 7) = 330 + 448 + 721 = 1,499\text{ cycles} \quad \checkmark$$
